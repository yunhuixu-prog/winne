## 一、需求背景
**为什么要做：**
《》复盘中，暴露出大量需要「按人群分流」的策略机会，而性别是最基础的人群维度之一。当前编辑器在用户进入时没有对图片做性别识别，下游功能无法据此差异化呈现，所有用户共用同一套默认值与素材排序：

- AI Retouch 第二批规划了「男性风格」，需要先识别出男性用户才能精准推送、避免对女性用户造成干扰。
- 缩略图引导（按目标人群替换缩略图，如男性 / 美发款）、美型默认落点与套组个性化都依赖性别输入&mdash;&mdash;男女对下颌重塑、五官调整的诉求存在明显差异。
- 已落地的「人种前置检测」已验证「进入即检测 + 下游个性化」这条链路；性别检测是同一思路的延伸，可复用其落地框架。

**需求目标：**

- 在用户进入编辑器、载入待处理图片时做一次性别前置检测，输出性别标签，作为前置属性供下游功能（AI Retouch 风格排序 / 缩略图 / 美型默认落点 / 套组推荐等）调用，实现按性别的差异化呈现与个性化默认。
- 补齐端内性别维度的数据拆分能力，便于后续量化男 / 女用户的功能偏好与转化差异。

## 五、需求描述
1、需求内容
本需求为底层检测能力建设，仅产出性别检测结果与标签，不在本需求内做任何 UI / 功能呈现改动（下游个性化由各自需求承接）。

**1****、检测时机与对象**

- 时机：用户进入编辑器、载入待编辑图片时触发一次检测。
- 对象：用户当前进入编辑的图片（以主体人脸为准）。

**2****、检测输出**

- 输出性别标签（如 male / female / 未识别）。
- 由于生理性别字段较为特殊，需要避免直接以性别、男、女作为字段命名，以规避合规检查。
- 多人脸场景：需支持多人脸，并将生理性别标签照人脸序回传
- 无人脸场景：返回「未识别」 没有识别到就不上报
。

**3****、能力提供方式**

- 检测结果作为前置属性提供给下游功能调用，接入方式与现有「人种前置检测」保持一致。
- 本需求不做任何功能 / UI 呈现改动，仅产出检测能力与标签。

**4****、性能与异常**

- 检测需在进入编辑器链路中低耗时完成、不阻塞用户操作（耗时与降级策略参考人种前置检测）。
- 检测失败 / 超时：返回「未识别」，下游走默认（非个性化）逻辑，不报错、不打断用户。

具体新增埋点，可复用目前 editor_race_detect 事件与埋点结构，考虑之后可能会需要前置更多检测模型，需要思考未来的扩容弹性。
