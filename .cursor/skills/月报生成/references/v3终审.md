# v3 终审月报（Agent 执行）

对应 `memory/终审专家.md`。在 Phase B（v2）之后执行；**不得改动 v2**。

## 核心约束（必须遵守）

1. **`monthly_report_v2.md` 只读**：终审过程中**不得修改、覆盖或回写** v2 文件。
2. **修正只写入 v3**：所有整改后的正文写入 `{OUT}/monthly_report_v3.md`。
3. **审计意见单独落盘**：写入 `{OUT}/审核报告.md`；v2 的问题与整改意见写在审核报告中，不在 v2 上打补丁。

## 1. 输入

| 文件 | 用途 |
|------|------|
| `{OUT}/monthly_report_v2.md` | **审查对象（只读）** |
| `{OUT}/monthly_report_v1.md` | 数据骨架校验 |
| `{OUT}/下钻报告/*.md` | 下钻树、贡献占比 |
| `{OUT}/贡献度/s2_*贡献度.csv` | 数值、趋势表校验 |
| `memory/归因思路.md` | 格式与归因规范 |
| `memory/终审专家.md` | 审计维度与输出结构 |
| `KB_SKILL_ROOT/wiki/` | 知识库时序、marks 校验（见 [知识库](../../知识库/SKILL.md)） |

## 2. 执行顺序

1. 通读 v2，对照下钻报告与贡献度 CSV 做**数据真实性**核对
2. 对照 wiki 做**时序校验**、**量级校准**、**反事实**检查
3. 对照归因思路与终审专家 §3.2.1 做**格式与规范**审查（单行拆解、贡献度门槛）
4. 撰写 `{OUT}/审核报告.md`：
   - §1 因果逻辑与真实性审计（逐条 ✅/❌/⚠️）
   - §2 格式与规范审查
   - §3 注明「修改后全文见 `monthly_report_v3.md`」（**不要把 v3 全文粘进审核报告**）
5. 基于 v2 + 审核意见，生成 `{OUT}/monthly_report_v3.md`（可直接交付版）
6. （可选）Phase D/E：`python 计算脚本/convert_monthly_v2.py -o {OUT}`；若脚本支持 `--v3` 则生成 `monthly_report_v3_converted.md`

## 3. 输出

| 路径 | 说明 |
|------|------|
| `{OUT}/审核报告.md` | 审计意见；审查对象标注为 v2（只读） |
| `{OUT}/monthly_report_v3.md` | 终审修正后的完整月报（**默认可交付正文**） |

## 4. 禁止

- 修改、覆盖 `monthly_report_v2.md`
- 将 v3 内容写回 v2
- 无审计过程直接复制 v2 为 v3（v3 须体现终审整改）
