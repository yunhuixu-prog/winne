# 神舟注意事项

写 SQL / 用神舟临时查询跑数时遵守下列规则。  
**维护规则**：神舟出现本文件未收录的报错时，在对应分类下追加「报错原文要点 + 规避写法」；勿删已验证条目。

## 1. 分区条件必须可解析为字面量日期

**报错要点**：`表[...]查询时指定的时间分区格式有误`（常见于 `sdk_odz_active` / `sdk_odz_new_device_info`）

**原因**：`date_p BETWEEN date_sub(...) / last_day(...)` 等动态表达式，神舟分区校验无法通过。

**规避**：
- 分区过滤使用字面量或调度参数：`date_p BETWEEN 20260101 AND ${start_time}`，或 `${start_time_pre29}` / `${start_time_last_day}` 等已算好的参数。
- `date_sub` / `last_day` 只放在**已扫入分区后的中间结果**上做计算，不要写进分区 WHERE。

## 2. JOIN 两端都必须是子查询

**报错要点**：`Join两端都必须是子查询`

**规避**：
```sql
-- 错误
LEFT JOIN stat_ab.filing_odz_active_user_profile p ON ...

-- 正确
LEFT JOIN (
  SELECT gid, date_p, ...
  FROM stat_ab.filing_odz_active_user_profile
  WHERE date_p BETWEEN ${start_time} AND ${end_time}
) p ON ...
```
两侧都要带可解析的 `date_p`（或表对应分区字段）范围。

## 3. 多表同名列必须加别名

**报错要点**：`Column xxx Found in more than One Tables/Subqueries`

**规避**：JOIN 后凡出现在 SELECT / GROUP BY / 表达式中的列一律 `v.col` / `w.col`，不要写裸列名（如 `country_code`、`date_p`）。

## 4. 慎用 WITH（CTE）

**报错要点**：`missing ) at 'fa'` / CTE 解析失败；日志里可见神舟把 `insert overwrite directory ...` **插在最后一个 CTE 与主 SELECT 之间**。

**规避**：
- 神舟临时查询优先用嵌套子查询，避免 `WITH ... AS () SELECT`。
- 若必须用 CTE，确认目标环境支持且不要依赖「CTE 后直接 UNION」的脆弱结构。

## 5. Presto 超时则换 Hive

**报错要点**：`Query exceeded maximum time limit of 3.00m` /「大查询请切换引擎重试」

**规避**：同一 SQL 改用 `--engine hive`（Hive on Spark）重跑；复杂窗口、大表活跃扫描优先按 Hive 写。

## 6. 引擎与函数差异

- `date_add` / 部分日期函数：注释里常见「这个要用 hive」。
- Presto 与 Hive 对 `` `time` ``、map 取参 `params['x']`、`nvl`/`coalesce` 支持略有差异；不确定时先 Presto，失败再 Hive，并把新差异补进本文件。

## 7. Hive 临时查询：嵌套里勿用 LATERAL VIEW / GROUPING SETS / ROLLUP 造「整体」

**验证工作流**（神舟 Hive on Spark，2026-07）：

| 任务 | 报错 | 原因与处理 |
|------|------|------------|
| 35132567 | `Invalid column reference 'market'` | `LATERAL VIEW EXPLODE` 后用 `market_rows.market` 限定引用，当前环境不支持 |
| 35132568 | `Invalid column reference 'market'` | 改成裸列 `market` 仍失败 → 嵌套查询里 LATERAL VIEW 别名透传差 |
| 35132569 | `Invalid column reference 'country'` | `GROUPING SETS` 同时出国家+整体时，嵌套字段在扩展聚合中无法解析 |
| 35132570 | `Invalid column reference 'country'` | 改 `WITH ROLLUP` 仍失败 |
| 35132571 | `Invalid column reference 'market_name'` | 字段改名仍失败 → 非保留字/重名，是 ROLLUP 兼容性 |
| 35132572 | `Invalid column reference 'market_name'` | 普通 `GROUP BY` 已可解析，但外层 `ORDER BY result.market_name` 经神舟包成 `INSERT OVERWRITE DIRECTORY` 后无法引用 |
| 35132574 | `Progress check failed (Server error 504)` | **进度接口临时超时，不是 SQL 失败**；客户端自动重试后可继续并成功 |

**最终解决方式**（成功：四国 `35132573`，整体 `35132574`）：
1. **不用** `LATERAL VIEW EXPLODE`、`GROUPING SETS`、`WITH ROLLUP` 生成「整体」。
2. 分市场：普通 `GROUP BY market_name, function_name`（或所需维度）。
3. 整体：相同明细口径，**另起一条 SQL** 只按 `function_name`（或所需维度）聚合。
4. SQL 内去掉非必要外层 `ORDER BY`；下载后本地排序、合并。

**沉淀经验**：神舟 Hive 临时查询、嵌套子查询中尽量只用**基础 `GROUP BY`**；需要「整体」行时拆成第二次查询，勿在一次 SQL 里用扩展聚合/炸裂造整体。

## 8. 进度接口 504 不等于查询失败

**报错要点**：`Progress check failed (Server error 504)`

**规避**：先区分是进度轮询超时还是任务本身失败；可等待自动重试或稍后查任务状态。勿因 504 立刻改 SQL / 重提同逻辑查询（例：35132574 重试后成功）。

## 9. 订单续费/合约关联勿用 `paid_oda_all_order_summary.contract_id`

**报错要点**：`Invalid table alias or column reference 'contract_id'`（列清单无 `contract_id`）；Presto 侧常表现为 `Column 'contract_id' not found in any table` /「请切换引擎重试」

**规避**：
- `stat_vip.paid_oda_all_order_summary` **无** `contract_id` 字段；按合约续费/解约关联改用 `stat_vip.paid_oda_vip_all_order`（需 `date_p` 快照分区 + `app_id_p` / `commodity_id_p` / `order_type='2'` / `contract_id<>0`）。
- 解约表仍用 `stat_vip.paid_oda_vip_tb_contract`。
- 此类多表 `contract_id` 关联优先 **Hive**。

## 10. 归因表与订单表 `contract_id` 类型不一致

**报错要点**：`Wrong arguments 'contract_id': Unsafe compares between different types`

**规避**：JOIN / 过滤前统一 `cast(contract_id as bigint)`（`filing_onz_sub_source_event_detail` 与 `paid_oda_vip_all_order` / `paid_oda_vip_tb_contract` 之间）。
