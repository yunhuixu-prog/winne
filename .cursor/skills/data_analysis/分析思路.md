# 分析思路

AirBrush 数据分析师日常工作的步骤与分流。执行具体动作时仍以子 skill 为准；本文只定「先做什么、后做什么」。

## 0. 接到需求时先澄清（缺一则问）

| 维度 | 要确认什么 |
|------|------------|
| 目标 | 临时看数 / 异动归因 / 周报月报 / 专题 / 实验？ |
| 指标 | 活跃 / 功能 / 订阅 / 成本 / 其他？ |
| 时间 | 日 / 周 / 月；起止日期（默认自然周/自然月口径与周报月报 skill 一致） |
| 切面 | 平台、国家、新老、渠道/自然、版本、付费状态等 |
| 产出 | 口头结论 / CSV / Markdown 报告 / 写入指定目录 |

信息足够则直接开跑，不要为「完美澄清」阻塞已可执行的取数。

## 1. 场景分流

```text
需求
 ├─ 「更新事件埋点」            → 更新埋点知识（§2.1）
 ├─ 只要看板已有指标          → 看板取数（§2）
 ├─ 看板没有 / 需明细或自定义  → 神舟 SQL（§3）
 ├─ 固定周期报告               → 周报 / 月报（§4）
 ├─ 解释波动 / 找事件          → 归因 + 知识库（§5）
 ├─ AB / 续费 / 双周会专项     → 对应实验·SOP skill（§6）
 └─ 多步专题（取数+归因+结论） → 按 §7 串联
```

## 2. 临时取数（看板）

1. 在 **`raw_data/看板说明/看板.csv`** 按指标名匹配行，记下 `dashboardId`、`chartId`、网关、筛选、备注。
2. 用 beidou-dashboard-data：探测 linkage → 二次带 filters 取数。
3. 整理结果：时间对比（环比/同比）、Top 国家或切面；注明看板与筛选条件。
4. 若备注提示近 N 天留存为 0、累计毛利≠日毛利加总等，结论中写明，避免误读。

### 2.0 订阅归因多级看板（必读 mapping）

查「某功能 / 子功能订阅人数、订阅链路来源」时，**先读** [`raw_data/订阅归因层级/`](raw_data/订阅归因层级/README.md)，再选层取数：

| 层级 | dashboardId | 筛选项 | 用途 |
|------|-------------|--------|------|
| L1 | 10015758 | 分类 | Edit / Else / … |
| L2 | 10015759 | 分类 + 二级归因 | Edit-Retouch、Edit-Edit 等 |
| L3 | 10015763 | + 三级归因 | 如 Edit-Retouch—AI Retouch |
| L4 | 10015764 | + 四级分类 | 三级下的素材/子项 |

- **权威分级表**：[`raw_data/订阅归因层级/官方分级mapping.csv`](raw_data/订阅归因层级/官方分级mapping.csv)（`source_*` → first/second/third/fourth_source）。查功能时先按功能名 / `source_0` 检索该表再填看板筛选。
- 查「XX 下子功能」：确认 XX 落在 L2 还是 L3 → 上级选到 XX → 用下一级「整体」或分布图拆子项；指标优先「订阅成功人数 / 订阅成功付费人数」。
- 近 7 天付费可能偏低（链路回填，见看板说明备注）。

## 2.1 更新事件埋点

1. 读 `raw_data/埋点事件/update_state.json` 水位；CF 版本目录 = 知识库 `site_632691935`。
2. 待拉 = CF 中 **> 水位** 的版本；大禹 Airbrush / OCI 增量拉取并更新 `dayu_gt722*`。
3. **每次**合并 `事件清单（手动版）.csv` → `事件知识_检索.csv`。
4. 推荐命令：`python3 scripts/update_event_tracking.py`（见 skill 专节）。

## 3. 临时取数（神舟）

1. 涉及事件表时：先查 **`raw_data/埋点事件/事件知识_检索.csv`**（含手动版）。**未找到事件/key/值口径 → 先问用户**，勿编造。
2. 在 `app/AB-OCI/口径/`、`说明/`、同类 `实验/`/`看板/` OCI 脚本中找口径；**禁止** BigQuery 旧脚本。
3. 按 `hive_sql_create` 写 Presto/Hive SQL（参数风格与周边一致）。
4. **把完整 SQL 发给用户确认**；未确认不得提交神舟。
5. 用户确认后：`shenzhou-temp-query --wait --download`；失败则改 SQL → 再确认 → 再跑。
6. 结果落盘路径告知用户；复杂口径在回复里用一句话说明依据文件。

## 4. 周报 / 月报

| 需求 | 调用 |
|------|------|
| 近期周报 / 指定周 | `周报生成`（默认至 v3 + converted） |
| 近期月报 / 指定月 | `月报生成` |
| 仅格式转换 / 仅终审 | 按对应 skill 的触发表，不要整条流水线重跑 |

报告生成后若用户追问「为什么涨跌」，进入 §5，不要只复述报告原文。

## 5. 异动归因

推荐顺序（可按已有数据跳步）：

1. **确认异动**：指标、幅度、时间窗、是否季节性（对比上周/上月/去年同期）。
2. **下钻定位**：平台 → 国家 → 新老 / 渠道自然 → 功能或订阅链路（看板或已有下钻 CSV）。
3. **知识库 QUERY**（`知识库` skill）：marks → 历史周报 → 节假日 → 产品需求。
4. **逻辑链**：数据事实 → 外部/产品事件 → 机制解释；分不清则标「待验证」并建议补取数。
5. **输出**：结论 + 证据（数表/看板/知识条目）+ 可选下一步取数清单。

周报月报内的归因步骤以各自 `memory/归因思路.md` 为准；专题归因可精简，但仍遵守「先数据后故事」。

## 6. 实验与固定 SOP

| 类型 | 入口 |
|------|------|
| 商业化冲突指标 | `ab-experiment-conflict` |
| 历次续费率宽表 | `ab-renewal-rates-date-p` |
| 双周会指标 | `biweekly-data-sop` |
| 其他实验 SQL | 优先复用 `app/AB-OCI/实验/` 下已有脚本，缺则按 §3 新写 |

实验分析默认：明确实验名、日期、abcode、是否新用户；跑完对照核心指标与冲突指标再下结论。

## 7. 专题分析（串联）

典型路径：

1. 定义问题与成功标准（一句话）。
2. 看板快速摸底（§2）→ 缺口用 SQL 补（§3）。
3. 必要下钻 / 贡献度（可参考周报月报 s1/s2 思路，不强制跑全流水线）。
4. 知识库命中（§5）。
5. 结构化输出：背景 → 数据发现 → 归因 → 建议 / 风险。

## 8. 交付与复盘

- 交付物写清：数据截止日、筛选口径、文件路径。
- 新坑记入 `注意事项.md`；神舟 SQL 类记入 `hive_sql_create/神舟注意事项.md`。
- 可沉淀的看板映射：优先更新 **`raw_data/看板说明/看板.csv`**；订阅分级更新 **`raw_data/订阅归因层级/`**（官方表用 `官方分级mapping.csv`）；埋点事件写入 **`raw_data/埋点事件/`**；其他口径仍改 `app/AB-OCI/口径/`。
